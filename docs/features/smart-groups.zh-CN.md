# 智能分组

[English](smart-groups.md)

智能分组是**独立的动态节点集合**，不会替换原分组，也不会修改节点的 `Group`。同一节点可以同时属于多个智能分组。候选节点满足**任意一项**即可：已保存的落地国家（`LinkCountry`）属于所选国家；节点原名/显示名命中所选国家的规则或独立的两位国家代码；或节点名称包含可选关键词（不区分大小写）。这三者是“或”关系，已保存国家与名称暗示的国家不同也能按名称命中。选了原分组时仍需同时满足原分组限制，可用成员仍须通过测速条件。名称命中不会改写节点保存的落地国家，也不代表落地 IP 已核实。

## 适用场景

- **跨机场汇总地区节点：** 把多个机场里的英国、法国、德国节点汇成一个优选池，不需要改动它们的原分组。
- **只订阅当前可用节点：** 要求延迟检测成功，按需再设置速度下限；检测失败或过期的节点自动退出集合。
- **在客户端更新订阅前完成检测：** 提前安排定时检测，供 OpenClash 等独立客户端拉取。SublinkPro 不控制客户端的更新时间。
- **排查节点为什么没进组：** 查看全部候选的来源机场、匹配依据和排除原因，可单独重测，也可重测全部候选。

## 国家匹配与协议分离

选择国家/国旗不会选中协议。名称中的准确国旗（如 `🇹🇷`）和独立 ISO 代码（`TR`）即使没有配置国家规则也能命中。智能分组名称规则中，纯两/三字母缩写按英文字母边界匹配：`TR` 不再命中 `trojan`，`ES` 不再命中 `vmess`/`vless`，`IN` 不再命中 `Singapore`。完整国家名称、国旗及显式自定义正则分支保持原行为。已有规则无需重写即可生效；通用国家规则测试/导入的行为不变。

保留原有“已保存国家、名称国家线索、手填关键词”三者的或关系。主动输入 `trojan` 关键词仍会匹配包含该词的节点名称，但不等于按协议字段筛选；真实土耳其节点可以使用任何协议。已保存的 `LinkCountry` 仍可作为国家条件，不会自动纠正：若此前按名称填充已误写为 `TR`，请核实落地国家后修改该节点资料。名称匹配不会改写节点数据。


## 使用方法

1. 在**订阅 → 智能分组**创建分组，从完整的可搜索国家/地区列表（包含菲律宾 PH）选择国家，可填作为“或”条件的名称关键词，以及作为“且”条件的原分组限制，并设置最大延迟、最低速度和结果有效期（默认 72 小时）。原分组留空表示跨全部原分组；新建分组默认不限制最大延迟。数值阈值为 0 表示不设该上限/下限；有效期为 0 表示不检查过期。
2. 点击**查看候选节点**打开候选弹框；即使还没有测速，也会显示所有匹配节点及各节点的可用状态或首个排除原因。在弹框中选择**检测方案**，点**检测候选节点**可测全部，点击行内**测此节点**只测单个节点。批量操作异步检测满足“国家或名称/关键词”，且符合可选原分组限制的全部候选节点，包括失败或未测节点。最低速度为 0 时，TCP 延迟检测策略就可以入组；最低速度大于 0 时，需要使用 mihomo 下载测速策略。弹框会监听测速任务完成事件并尝试刷新；错过事件或重新打开时也可手动点击**刷新**。
3. 节点必须有**成功且大于零**的延迟检测结果，满足可选延迟上限，并且延迟检测时间在有效期内（有效期为 0 时不检查）。若最低速度大于 0，还要求速度检测成功、达到速度下限且速度检测时间未过期。每次查询动态计算成员，失败或过期节点会自动退出。
4. 在智能分组卡片点击**用此分组创建订阅**，可跳转到新增订阅并预选该分组。也可以在订阅的**新增/编辑 → 节点选择**直接选择智能分组；选择框在手动模式下也可见，选中时会自动切为动态模式（已有手动节点时为混合模式）。要加入现有订阅，打开该订阅的编辑页面选择即可。订阅列表另行展示智能分组数量，而不是把它算作物理节点/原分组。生成订阅时实时取得当前成员，然后执行原有过滤与按有效名称去重。直接节点、原分组和机场排在智能分组成员之前；预览使用相同的成员条件。

被订阅引用的智能分组不能删除，须先在订阅中移除。手动和自动候选检测使用的策略都只提供检测参数，不限制到策略保存的分组或标签范围。

成员接口返回 `candidateCount`（健康筛选前的候选数）、`statusCounts`（互斥的排除原因计数）、全部可用成员 ID、前 100 个可用节点样本 `nodes`，以及分页的全部候选明细 `candidateNodes`（查询参数 `page`、`pageSize`，默认每页 30、最多 100）。候选明细同时包含来源机场 `airportId` / `airportName`（与原 `group` 分开显示）、测速状态、首个排除原因，以及 `includedBySmartGroup`：只有当前通过智能分组检测规则才为 true。无机场且 ID 为 0 表示手动节点；非零 ID 但机场名称为空表示原机场已删除。弹框用“已入组 / 未入组”表示节点当前是否满足本分组规则。最终订阅还可能经自身过滤、脚本和有效名称去重，不能把此状态理解为已出现在每条订阅中。弹框使用单层滚动的紧凑候选列表（手机端全屏），在无需横向滚动的情况下展示简明可用状态、排除原因、原分组/来源机场、延迟/速度以及单节点测速。未测速/失败节点不会从弹框隐藏。展示样本的 `countrySource` 标明展示的国家是已保存还是按名称推断；`matchSource` 标明本次是落地国家、名称国家还是关键词命中。节点可能保存为 GB，却因名称命中 PH 分组；这不代表其落地 IP 为 PH。候选数为 0 时，请检查 `LinkCountry`、名称国家规则及关键词/原分组；有候选但无成员时，页面会列出检测未成功、阈值不满足和结果时间过期/缺失的数量。订阅本身的国家白/黑名单随后仍按节点已保存的 `LinkCountry` 判断，因此仅名称命中的节点可能被订阅国家白名单排除。测速接口可选传 `nodeId` 仅检测当前智能分组的指定候选，省略或传 0 则检测全部。国家列表不依赖于当前节点是否存在该国家；批量按名称填充国家后会立即同步节点缓存。不会实际创建或移动节点原分组。


## 自动检测

编辑分组，在**自动检测**中配置：

- 选择**默认检测方案**。策略本身不必启用定时任务。最低速度为 0 时可用 TCP；最低速度大于 0 时须使用 mihomo 下载测速策略。被引用策略不能删除，需先清空或更换分组保存的策略；有下载速度要求的自动分组所用策略不能改为 TCP。
- 打开**定时检测**，设置五段 Cron（分 时 日 月 星期），例如 `0 3 * * *` 表示每天 03:00。保存后即时替换计划；关闭/删除会移除任务，服务启动/重载会恢复计划。旧分组的两个自动开关默认均关闭。
- 按需打开**机场更新后检测**。机场更新成功后，只检测“该机场当前节点”与“各智能分组候选”的交集；包含未变化、此前失败及未测节点。不检测其他机场或不匹配节点。同一次更新批次内，同一策略的多个分组共享去重后的节点列表。机场更新失败不触发联动。

Cron 使用 **SublinkPro 服务/容器本地时区**，不是浏览器或 OpenWrt 时间。卡片显示服务端计算的下次执行时间，编辑器提示服务时区偏移；通用 Cron 编辑器预览使用浏览器时间。配置前请核对部署时区。

同组手动、定时和机场更新检测不会重入：手动重复请求返回 HTTP 409，定时触发遇到运行中则跳过。检测期间收到机场更新会合并排队，完成后重新读取最新配置/候选补测，覆盖期间新增节点。候选为空直接跳过，绝不退回策略范围或全库。这是**每组防重**，不是全局节点锁：不同分组、独立策略测速和机场既有的**更新后检测**仍可能检测同一节点。机场原开关独立保留，除非确实要重复检测，否则不要对相同节点/策略同时启用两条流程。

结果沿用正常检测流程保存，再动态决定成员，不移动/复制节点。**上次检测开始**是最近一次候选检测开始时间，不是完成或全部通过；实际结果看任务进度/历史和候选排除原因。列表/创建/更新响应及成员接口的 `checkInfo` 包含只读 `lastCheckAt`、`nextCheckAt`、`checkRunning`、`checkTimezone`。页面在任务完成时刷新，打开期间也会轮询自动状态。

### 在外部订阅更新前准备节点

例如 OpenClash 每天 04:00 更新订阅，可安排机场 02:30 更新并启用机场更新后检测，按需再设分组 03:00 全候选检测。根据节点数、并发及超时留足缓冲，示例时间不保证完成；结果有效期应大于检测间隔加刷新缓冲。OpenClash 仍在 OpenWrt 独立运行，SublinkPro **不控制它，也不等待它**。拉取订阅读取当前通过检测成员，不触发测速，也不等待运行中的任务。


## 检测中心任务

也可在[检测中心](unlock-check.zh-CN.md#检测中心)建立独立任务，复用方案、检测本组候选，并按需前置更新指定机场。不要同时为相同节点启用重复自动检测路径。检测中心的 AI 服务结果仅作独立检测结果，现有智能分组入组规则不会自动变成 AI 筛选规则。
